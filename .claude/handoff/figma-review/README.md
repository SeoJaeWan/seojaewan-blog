# 피그마 디자인 시스템 검토 인계

다른 PC의 새 세션에서 이어 하기 위한 자료다. 정해진 규칙은 `.codocs`가 기준이고, 여기는 작업 상태와 작업 자료만 둔다. 검토가 끝나면 이 폴더는 지운다.

## 지금 상태 (2026-11-28)

- 피그마 파일 키 `XV9Y1UT5UH4tC5hSqLVipZ`.
- 조립 여덟(Desktop, Taskbar, Start, Search, Chrome, Article, Explorer, Windows)을 조립마다 `Patterns / <이름>` 페이지에 그렸다. 왼쪽 열이 PC의 `흐름`·`키보드 흐름`, 오른쪽 열이 `모바일 흐름`·`모바일 키보드 흐름`이다. 노트북은 흐름도를 그리지 않는다.
- 정한 것은 `.codocs`에 모두 반영했다. 문서가 코드보다 앞서 있고, 코드로 옮길 일은 `.codocs/planning/todo.yaml`에 있다.

## 이어 할 일

1. 답을 기다리는 물음 셋을 하나씩 묻는다(`todo.yaml`의 "정해야 할 것"에도 있다).
   - 모바일 탐색기 명령 모음에서 `잘라내기` · `이름 바꾸기` · `삭제`를 뺄지. 터치에는 골라 둔 항목이 없어 손가락으로는 늘 비활성이다. 낸 의견은 "뺀다, `붙여넣기`는 남긴다"였다.
   - 접근성 패널의 자리를 PC(네 구석)와 모바일(위·아래)이 따로 기억할지.
   - 폭 320 작업 표시줄에 버튼 다섯과 시계가 들어가는지. 390에서도 시계와 15 겹쳐 버튼 묶음을 왼쪽으로 당겨 그렸다. 320은 먼저 그려서 확인한 뒤 묻는다.
2. 부품(컴포넌트) 재정비. `todo.yaml`의 "부품을 재정비할 때 볼 것"과 `parts-survey.json`을 논의 목록으로 먼저 짧게 보여 주고 하나씩 논의한다.
3. 그 뒤에 남은 것: 흐름도를 e2e 테스트에 잇는 방법, Screens의 노트북 그림, 옛 Patterns 견본 정리.

## 알려진 흠

- Start의 범주 폴더를 열었을 때 안의 글 아이콘이 거의 안 보인다(부품 문제, PC도 같다).
- 창 버튼(최소화, 닫기)에 포커스 변형이 없다.
- 모바일 흐름은 프로토타입 연결 없이 세트 설명의 줄로만 그렸다.

## 파일

| 파일                                     | 내용                                                                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `decisions.md`                           | 모든 결정의 시간순 기록. 뒤의 것이 이긴다. 변형 id와 작업 중 배운 것도 있다. 끝부분부터 읽는다                        |
| `keyboard-map.md`                        | 조립별 키보드 기능 표                                                                                                 |
| `mobile-survey.md`, `mobile-progress.md` | 모바일 조사와 만든 변형 id                                                                                            |
| `parts-survey.json`                      | 부품 76개 조사(안 쓰이는 것, 덮어쓰기, 이름 어긋남)                                                                   |
| `figma-state.json`                       | 페이지·세트·섹션 id                                                                                                   |
| `draw-flow-arrows.js.txt`                | 세트 설명의 `흐름:` 줄과 프로토타입 연결을 읽어 화살표를 그리는 피그마 스크립트. lint가 건드리지 않게 `.txt`로 두었다 |
| `crop.swift`, `crop2.swift`              | 캡처를 잘라 낱장으로 보는 스크립트                                                                                    |
| `memory/`                                | 이전 PC의 작업 메모리(작업 방식에 대한 지시와 합의). 새 세션의 메모리 폴더에 옮겨 쓴다                                |

파일 안의 `<scratchpad>` 경로는 이전 세션의 임시 폴더라 지금은 없다. 캡처는 옮기지 않았으니 필요하면 다시 받는다.

## 작업할 때

- 피그마에 쓴 것은 낱장을 직접 눈으로 확인한 뒤 보여 준다. 넘침·잘림은 숫자만 믿지 않는다.
- 다른 변형의 인스턴스로 새 모습을 만들면 그 변형의 연결을 물려받는다. 떼어 낸 복사본으로 만들고, 인스턴스인 채로 연결을 지우지 않는다(원본의 연결이 지워진 적이 있다).
- 피그마 쓰기는 한 번에 하나씩 차례로 하고, 호출마다 페이지는 한 번만 바꾼다.
