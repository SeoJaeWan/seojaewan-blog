2026-10-23 대화에서 피그마 일치 검사를 다음 방향으로 바꾸기로 합의했고, 같은 날 `.codocs` 11개 문서에 반영했다(브랜치 docs/figma-restructure-decisions, 커밋 전). 코드(판정 도구·플러그인·CI·토큰 생성기 삭제·스킬)는 아직이다. 같은 날 개편안 초안을 만들어 보여 줬다(브랜치 `feat/figma-<컴포넌트>`, `feat/figma-tokens`. 결정 번호는 문서에 넣지 않음. 절대 위치 거리는 판정하지도 막지도 않음. 팝업 위치 덮어쓰기는 플러그인이 자동으로 막음). 사용자 확인 뒤 문서를 고친다.

- 자동 판정은 객관적인 것만: 입력값(설정값·연결 이름)이고 피그마↔CSS가 1:1인 속성만 이름+값으로 비교. HUG/FILL, 안쪽 선, 재질, 줄바꿈 결과, 위치는 판정에서 빼고 사람이 캡처 표로 본다. 픽셀 비교는 쓰지 않는다.
- 클래스 이름 대신 CDP로 이긴 CSS 선언의 `var()`를 읽는 방식 검토(미검증).
- 자산은 파일 사슬(`generate:assets --check` + `data-asset`)로 100% 일치.
- 1컴포넌트 1PR(브랜치 고정), 토큰은 전용 PR `feat/figma-tokens`로 먼저 병합. 토큰 이름 변경은 추가→옮기기→지우기. 토큰 PR은 영향 컴포넌트 PNG도 갱신(같은 내보내기에 포함된 컴포넌트 PNG는 컴포넌트 PR에만).
- CI 실행은 바뀐 파일로 영향 범위 자동 계산, `figma` 라벨은 결과로 자동 부착. 판정 통과 후 캡처해 `피그마 | 코드` 댓글(초안 PR 포함). main 병합 시 `parity-captures` 브랜치에 캡처 저장, 플러그인 PR 본문은 `피그마 | 현재 구현`.
- 생성 파일은 CI 자동 커밋하지 않고 수동. 대신 스킬 두 개(`figma-token-pr`, `figma-component-pr`)를 도구 변경 뒤에 만든다. 스킬은 절차만 담고 규칙은 `@codocs [[...]]` 링크로 둔다([[codocs 연결 규칙]]에 스킬 추가 필요).
- 토큰 생성기(`scripts/tokens/`)는 없앤다. `tokens.css`는 사람·에이전트가 `tokens.json`+피그마를 보고 직접 쓰고, CI의 "토큰 값 비교"가 이름 규칙·값 변환으로 1:1 토큰만 확인(그라데이션·재질·효과 묶음은 캡처 표). 컴포넌트 판정의 기대값도 `var()` 계산값이 아니라 `tokens.json` 값이어야 함. 자산 생성기는 남김. 섹션 이름 "토큰 생성"→"토큰 작성".

**Why:** 이름 비교 방식이 번역 규칙(class-rules)과 결정 사항(20개)을 계속 늘리며 주관적이 되어 "산으로 간다"는 문제 제기에서 나왔다.
**How to apply:** 피그마 일치 검사 관련 작업을 이어갈 때 이 방향을 기준으로 하되, 문서에 반영됐는지 먼저 `.codocs`에서 확인한다.
