# 조립의 모바일 조사 (읽기만 함)

근거: `.codocs/features/**`의 모바일 문장, `design-system.yaml`의 기기 변형, 옛 `Patterns`·`Screens`의 모바일 견본, 앱 코드(`apps/web/src`)의 `device === 'mobile'` 분기, Desktop 세트 설명의 `흐름:` 줄.
한계: 조립 세트 설명의 `흐름:` 줄은 Desktop만 원문을 읽었다(한 세트가 수백 줄). 나머지 일곱은 앞선 제작·검수 보고의 기능 목록으로 갈랐다. 그래서 아래 개수는 "흐름 줄 수"가 아니라 "기능 묶음 수"다.

## 0. 화면 크기와 있는 화면

- 모바일 390×844 (`Screens`의 `모바일 (390×844)`), 모바일 최소 320×568.
- Screens 모바일 화면 7장: M-1 바탕화면 `100:12960`, M-2 Start `100:13092`, M-3 검색 입력 전 `592:8840`, M-4 검색 결과 `100:13286`, M-5 탐색기 `100:13455`, M-6 Chrome 글 `100:13641`, M-7 미리보기 목록 `3497:16763`. 최소 화면 7장(T-1~T-7, 재부팅 화면 `1898:10683` 포함).
- 직접 본 그림(M-1, M-2, M-5, M-6):
  - 바탕화면: 아이콘이 왼쪽 열에 세로로. 작업 표시줄은 시작 · 검색 버튼(돋보기) · 탐색기 · Chrome · 시계. 접근성 모드 아이콘·버튼은 견본에 없다(견본이 그 결정보다 앞섬).
  - 탐색기: 제목 표시줄(앱 아이콘 · 제목 · 최소화 · 닫기), 주소 줄(뒤로 · 경로 한 칸 · 검색 버튼), 명령 모음은 아이콘만 일곱(새 폴더 · 잘라내기 · 붙여넣기 · 이름 바꾸기 · 삭제 · 정렬 · 보기), 본문, 상태 줄(개수만, 보기 버튼 없음).
  - Chrome: 제목 표시줄(앱 아이콘 · 제목 · 최소화 · 닫기), 도구 모음(뒤로 · 주소창 · ⋮), 글(좁은 모양, 목차 접힘).
  - Start: 화면 폭을 채운 패널이 작업 표시줄 바로 위에 틈 없이. 검색 띠, 고정됨 4열, 모두, 사용자 띠.

## 2. 모바일에만 있는 것

- 작업 표시줄의 검색 버튼(검색 상자 대신).
- 세로로 쌓은 미리보기 목록(`TaskbarPreviewList` Device=Mobile, `WindowPreview` Variant=Title).
- 창의 제목 표시줄(앱 아이콘 · 제목 · 최소화 · 닫기). 최대화가 없다(코드 `hasMaximize={false}`).
- Chrome ⋮ 메뉴의 앞으로 · 새로고침(`Menu/ChromeMoreMobile`).
- 탐색기의 검색 줄(← + 검색 상자), 경로 한 칸, 아이콘만 있는 명령 모음.
- 화면을 채운 Start·검색 패널(틈 없음), 고정됨 4열, 추천 3개.
- 접근성 패널의 한 줄 꼴(결정 3, 아직 그림 없음).
