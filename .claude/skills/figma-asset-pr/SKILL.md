# 피그마 자산 PR 처리

입력: `feat/figma-assets` PR 번호.

이 스킬은 절차만 담는다. 규칙은 아래 `@codocs \[[문서:섹션]]` 링크가 가리키는 섹션에 있고, 실행할 때 codocs MCP의 `codocs_get`으로 그 섹션을 읽어 따른다. 규칙을 이 파일에 옮겨 적지 않는다.

이 스킬이 따르는 섹션: @codocs [[디자인 시스템:스킬]]

## 하지 않는 것

- @codocs [[디자인 시스템:스킬]]에 적힌 하지 않는 것(피그마에서 온 자료 고치기, 생성 파일 손으로 고치기, 병합)과 멈추는 경우를 따른다.
- 생성은 CI가 한다(@codocs [[디자인 시스템:CI]]). 생성기를 로컬에서 돌려 결과를 커밋하지 않는다.
- `.codocs` 고치기. 고쳐야 하면 무엇을 왜 바꿀지 사용자에게 제안하고 멈춘다(@codocs [[개발 컨벤션:작업 원칙]]).

## 절차

1. 문서를 읽는다.
   - @codocs [[디자인 시스템:자산]]
   - @codocs [[디자인 시스템:아이콘 자리]]
   - @codocs [[디자인 시스템:PR 흐름]], @codocs [[디자인 시스템:CI]]
   - @codocs [[디자인 시스템:피그마 플러그인]]
2. PR 브랜치를 받는다(`gh pr checkout <번호>`). `main` 대비 바뀐 파일이 @codocs [[디자인 시스템:피그마 플러그인]]에서 자산 PR이 바꾸는 파일(자산 원본)과 changeset, CI가 생성해 커밋한 생성 파일뿐인지 확인한다. 예상 밖 파일이 있으면 멈추고 보고한다.
3. CI가 그 PR에 생성 파일을 커밋했는지 `gh pr checks <번호>`와 PR 커밋으로 본다. 생성이 아직 돌지 않았거나 실패했으면 멈추고 보고한다. 생성 파일이 들어왔으면 받아 온다(`git pull`).
4. `src/assets/`의 `main` 대비 변경을 세 묶음으로 정리한다: 더해짐, 바뀜, 이름 바뀜·지워짐.
5. 이름이 바뀌거나 지워진 자산을 쓰는 코드를 찾아 고친다(@codocs [[디자인 시스템:PR 흐름]]). 앱과 디자인 시스템 안의 옛 자산 이름 쓰는 곳을 검색하고, 같은 자리에 놓이는 새 이름의 자산으로 바꾼다. 쓰는 규칙(색 클래스, 크기)은 @codocs [[디자인 시스템:자산]], @codocs [[디자인 시스템:아이콘 자리]]를 따른다. 바꿀 새 이름이 분명하지 않으면 멈추고 보고한다.
6. changeset을 맞춘다(@codocs [[디자인 시스템:PR 흐름]]의 changeset, @codocs [[Git 작업 규칙:Changesets]]). 플러그인이 올린 changeset은 그대로 둔다. 앱을 고쳤으면 그 changeset에 앱(`apps/web`)을 더하거나 종류를 올린다.
7. 푸시하기 전에 CI의 검증 결과(`pnpm test` 등)는 PR 체크에서 본다. 로컬 확인은 두지 않는다(@codocs [[디자인 시스템:스킬]]). 다만 고친 코드의 옛 이름을 찾는 데 `pnpm lint`와 `pnpm typecheck`를 쓸 수 있다.
8. 커밋하고 푸시한다. 커밋 규칙은 @codocs [[Git 작업 규칙:커밋]]을 따른다. PR 브랜치에 이어서 커밋하고 병합하지 않는다.
9. 보고한다.
   - 바뀐 자산(더해짐, 바뀜, 이름 바뀜·지워짐)과 고친 코드
   - CI 체크 결과
   - 사람이 모습을 봐야 할 곳(자산이 바뀐 자리)
