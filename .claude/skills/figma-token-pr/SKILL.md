# 피그마 토큰 PR 처리

입력: `feat/figma-tokens` PR 번호.

이 스킬은 절차만 담는다. 규칙은 아래 `@codocs \[[문서:섹션]]` 링크가 가리키는 섹션에 있고, 실행할 때 codocs MCP의 `codocs_get`으로 그 섹션을 읽어 따른다. 규칙을 이 파일에 옮겨 적지 않는다.

이 스킬이 따르는 섹션: @codocs [[디자인 시스템:스킬]]

## 하지 않는 것

- @codocs [[디자인 시스템:스킬]]에 적힌 하지 않는 것(피그마에서 온 자료 고치기, 생성 파일 손으로 고치기, 병합)과 멈추는 경우를 따른다.
- 생성은 CI가 한다. 플러그인은 `tokens.json`만 올리고 `tokens.css`·`token-names.ts`는 PR의 CI가 만들어 커밋한다(@codocs [[디자인 시스템:토큰 검사]], @codocs [[디자인 시스템:CI]]). 생성 파일을 로컬에서 만들거나 고치거나 견주지 않는다.
- `.codocs` 고치기. 고쳐야 하면 무엇을 왜 바꿀지 사용자에게 제안하고 멈춘다(@codocs [[개발 컨벤션:작업 원칙]]).

## 절차

1. 문서를 읽는다.
   - @codocs [[디자인 시스템:토큰 생성]]
   - @codocs [[디자인 시스템:토큰 사용 강제]]
   - @codocs [[디자인 시스템:토큰 검사]]
   - @codocs [[디자인 시스템:PR 흐름]], @codocs [[디자인 시스템:CI]]
2. PR 브랜치를 받는다(`gh pr checkout <번호>`). `main` 대비 바뀐 파일이 @codocs [[디자인 시스템:피그마 플러그인]]에서 토큰 PR이 바꾸는 파일(`tokens.json`)과 changeset, CI가 생성해 커밋한 생성 파일뿐인지 확인한다. 예상 밖 파일이 있으면 멈추고 보고한다.
3. CI가 그 PR에 생성 파일을 커밋했는지 `gh pr checks <번호>`와 PR 커밋으로 본다. 생성이 실패했으면(규칙이 없는 변수 묶음, 같은 CSS 이름이 되는 토큰 등) 피그마나 문서를 고쳐야 하므로 멈추고 보고한다. 생성이 아직 돌지 않았으면 멈추고 보고한다. 생성 파일이 들어왔으면 받아 온다(`git pull`).
4. `tokens.json`(`src/tokens/`)의 `main` 대비 변경을 세 묶음으로 정리한다: 더해짐, 값 바뀜, 이름 바뀜·지워짐.
5. `pnpm lint`로 이름이 바뀌거나 지워진 토큰의 옛 클래스를 쓰는 코드를 찾는다(모르는 클래스로 나온다). 새 이름의 클래스로 고친다(@codocs [[디자인 시스템:PR 흐름]]). 바꿀 새 이름이 분명하지 않으면 멈추고 보고한다.
6. changeset을 맞춘다(@codocs [[디자인 시스템:PR 흐름]]의 changeset, @codocs [[Git 작업 규칙:Changesets]]). 플러그인이 올린 changeset은 그대로 둔다. 앱을 고쳤으면 그 changeset에 앱(`apps/web`)을 더하거나 종류를 올린다.
7. 푸시한 뒤 CI의 검증 결과는 PR 체크에서 본다. 피그마에서 온 것의 확인은 CI에서만 돈다(@codocs [[디자인 시스템:스킬]]).
8. 커밋하고 푸시한다. 커밋 규칙은 @codocs [[Git 작업 규칙:커밋]]을 따른다. PR 브랜치에 이어서 커밋하고 병합하지 않는다.
9. 보고한다.
   - 바뀐 토큰(더해짐, 값 바뀜, 이름 바뀜·지워짐)과 고친 코드
   - CI 체크 결과
