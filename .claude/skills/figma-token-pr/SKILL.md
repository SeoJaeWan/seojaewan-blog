# 피그마 토큰 PR 처리

입력: `feat/figma-tokens` PR 번호.

이 스킬은 절차만 담는다. 규칙은 아래 `@codocs \[[문서:섹션]]` 링크가 가리키는 섹션에 있고, 실행할 때 codocs MCP의 `codocs_get`으로 그 섹션을 읽어 따른다. 규칙을 이 파일에 옮겨 적지 않는다.

이 스킬이 따르는 섹션: @codocs [[피그마 연동:스킬]]

## 하지 않는 것

- @codocs [[피그마 연동:스킬]]에 적힌 하지 않는 것과 멈추는 경우를 따른다.
- `.codocs` 고치기. 고쳐야 하면 무엇을 왜 바꿀지 사용자에게 제안하고 멈춘다(@codocs [[개발 컨벤션:작업 원칙]]).

## 절차

1. 문서를 읽는다.
   - @codocs [[피그마 연동:토큰 생성]]
   - @codocs [[피그마 연동:토큰 사용 강제]]
   - @codocs [[피그마 연동:토큰 검사]]
   - @codocs [[피그마 연동:PR 흐름]]
2. PR 브랜치를 받는다(`gh pr checkout <번호>`). `main` 대비 바뀐 파일이 @codocs [[피그마 연동:피그마 플러그인]]에서 토큰 PR이 바꾸는 파일뿐인지 확인한다. 예상 밖 파일이 있으면 멈추고 보고한다.
3. `figma/tokens.json`의 `main` 대비 변경을 세 묶음으로 정리한다: 더해짐, 값 바뀜, 이름 바뀜·지워짐.
4. `pnpm --filter @seojaewan/design-system generate:tokens --check`로 저장소의 `src/tokens.css`가 변환 스크립트 결과와 같은지 확인한다. 다르면 고치지 말고 멈추고 보고한다.
5. 생성이 실패하면(규칙이 없는 변수 묶음, 같은 CSS 이름이 되는 토큰 등) 피그마나 문서를 고쳐야 하므로 멈추고 보고한다.
6. 토큰이 이미지를 쓰면 `pnpm --filter @seojaewan/design-system generate:assets`를 실행하고 결과를 함께 커밋한다.
7. `pnpm lint`를 실행한다. 이름이 바뀌거나 지워진 토큰의 옛 클래스를 쓰는 코드가 모르는 클래스로 나오면, 새 이름의 클래스로 고친다(@codocs [[피그마 연동:PR 흐름]]). 바꿀 새 이름이 분명하지 않으면 멈추고 보고한다.
8. `pnpm typecheck`, `pnpm test`도 통과시킨다.
9. 커밋하고 푸시한다. 커밋 규칙은 @codocs [[Git 작업 규칙:커밋]]을 따른다. PR 브랜치에 이어서 커밋하고 병합하지 않는다.
10. 보고한다.
    - 바뀐 토큰(더해짐, 값 바뀜, 이름 바뀜·지워짐)과 고친 코드
    - 캡처 범위(@codocs [[피그마 연동:캡처 범위]])와 CI 캡처 표에서 사람이 볼 곳(@codocs [[피그마 연동:캡처 표]])
