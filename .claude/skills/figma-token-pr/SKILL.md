# 피그마 토큰 PR 처리

입력: `feat/figma-tokens` PR 번호.

이 스킬은 절차만 담는다. 규칙은 아래 `@codocs \[[문서:섹션]]` 링크가 가리키는 섹션에 있고, 실행할 때 codocs MCP의 `codocs_get`으로 그 섹션을 읽어 따른다. 규칙을 이 파일에 옮겨 적지 않는다.

이 스킬이 따르는 섹션: @codocs [[피그마 일치 검사:스킬]]

## 하지 않는 것

- `figma/` 고치기, `src/assets/` 손으로 고치기, 병합.
- `.codocs` 고치기. 고쳐야 하면 무엇을 왜 바꿀지 사용자에게 제안하고 멈춘다(@codocs [[개발 컨벤션:작업 원칙]]).

## 절차

1. 문서를 읽는다.
   - @codocs [[피그마 일치 검사:토큰 작성]] (이름 규칙, 쓰는 방법, 토큰 값 비교)
   - @codocs [[피그마 일치 검사:경우별 흐름]] (토큰 이름 변경·삭제의 순서)
   - @codocs [[피그마 일치 검사:판정 항목]] (토큰 값 비교 표, 판정하지 않는 것)
2. PR 브랜치를 받는다(`gh pr checkout <번호>`). `main` 대비 바뀐 파일이 `figma/tokens.json`과 토큰이 쓰는 이미지(`figma/assets/`), 다시 내보낸 컴포넌트 변형 PNG(`figma/components/*/*.png`)뿐인지 확인한다. 예상 밖 파일이 있으면 멈추고 보고한다.
3. `figma/tokens.json`의 `main` 대비 변경을 세 묶음으로 정리한다: 더해짐, 값 바뀜, 이름 바뀜·지워짐.
4. 이름 바뀜·지워짐이 있으면 옛 이름을 코드(`src/`)가 아직 쓰는지 찾는다. 쓰고 있으면 고치지 말고 멈춘다. @codocs [[피그마 일치 검사:경우별 흐름]]의 순서(새 이름 더하기 → 컴포넌트 옮기기 → 옛 이름 지우기)로 나눠야 한다고 사용자에게 설명한다.
5. `src/tokens.css`를 `tokens.json`과 피그마를 보고 손으로 고친다. 생성기는 없다. 이름은 @codocs [[피그마 일치 검사:토큰 작성]]의 이름 규칙을 따른다. 처음 쓰는 스타일 종류(예: 방사형·각도 그라데이션)는 그 방법을 판단해 `tokens.css`에 처음으로 쓴다. 이름 규칙 표에 없는 변수 묶음이 생겼으면 규칙을 먼저 정해야 하므로 문서 변경을 제안하고 멈춘다.
6. 토큰이 이미지를 쓰면 `pnpm --filter @seojaewan/design-system generate:assets`를 실행하고 결과를 함께 커밋한다(손으로 고치지 않는다).
7. `pnpm test`를 실행한다(토큰 값 비교가 여기서 돈다). 통과할 때까지 5로 돌아가 고친다.
8. `pnpm lint`, `pnpm typecheck`도 통과시킨다.
9. 커밋하고 푸시한다. 커밋 규칙은 @codocs [[Git 작업 규칙:커밋]]을 따른다(Conventional Commits, 영어 제목, 한국어 본문). PR 브랜치에 이어서 커밋하고 병합하지 않는다.
10. 보고한다.
    - 바뀐 토큰(더해짐, 값 바뀜, 이름 바뀜·지워짐)과 `tokens.css`에서 고친 곳
    - 영향받는 컴포넌트(CI 비교 범위, @codocs [[피그마 일치 검사:비교 범위]])
    - 캡처 표에서 사람이 볼 곳: 값으로 판정하지 않는 그라데이션, 흐림, 재질 등(@codocs [[피그마 일치 검사:캡처 표]])
