# Start panel

실제 `Windows`, `TaskbarPanel`, `TaskbarRoot`, `TaskbarStartButton`을 runtime 순서로 조립한
기능 카탈로그다. 이 문서는 Start panel이 제공하는 기능과 상태 도구의 역할을 설명하며,
`동작 확인` Story에서는 같은 구성을 직접 실행할 수 있다.

실제 window 실행과 route 이동은 미래 소비 앱의 책임이다. 이 Storybook에서는 connector가
전달하는 semantic event까지 확인한다.

## 동작 상태

### 초기 상태

- **기본 상태**: 저장된 고정 항목이 없는 초기 상태
- **저장된 React 고정**: localStorage에서 React 시작 화면 고정을 복원한 상태
- **여러 항목 고정**: Context Menu의 순서 변경 action과 경계 상태를 확인할 수 있는 네 항목 상태

초기 상태가 바뀌면 item, storage, Provider와 발생 이벤트가 함께 초기화된다.

### 항목 변경

- **React 데이터 갱신**: 현재 Provider에 같은 ID의 최신 데이터를 전달
- **React 항목 제거**: 현재 Provider에 React가 제외된 전체 항목을 전달
- **전체 초기화**: item, storage와 발생 이벤트를 기본값으로 복원

항목 변경은 Provider를 다시 조립하지 않고 실제 `windowsItems` 갱신과 stale pin lifecycle을 유지한다.

## 검증 범위

Storybook은 실제 connector 구성을 직접 실행할 수 있는 기능 카탈로그다. `play`, assertion, browser
test와 smoke 검증은 포함하지 않는다.

단위 테스트는 panel lifecycle, keyboard 처리, Provider state, persistence, no-op, storage 실패 격리와
reducer·hook 경계 조건을 보장한다.

소비 앱은 실제 window 생성과 실행, route와 콘텐츠 연결, 앱 수준 정책과 전체 사용자 flow를 담당한다.
